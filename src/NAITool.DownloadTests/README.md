# Model download integrity regression tests

Run on Windows with the local .NET SDK:

```powershell
.tools/dotnet/dotnet.exe run --project NAI-Utility-Tool/src/NAITool.DownloadTests/NAITool.DownloadTests.csproj -c Debug
```

This executable links the actual download/catalog/integrity services. It uses the same ONNX Runtime DirectML package version as the application, but constructs default CPU sessions only. App-root/localization stand-ins prevent access to real user data. The embedded 103-byte ONNX fixture is an explicitly constructed IR-v8/opset-13 Identity graph with float input/output shape [1,1,1,1], not a real tagger or downloaded user model. All HTTP requests target a disposable localhost listener; a synthetic handler covers declared-length mismatch. Tests create and remove their own temporary directory.

Coverage: success, local manifest, changed/truncated finals, optional expected SHA-256 and response Content-Digest, invalid ONNX, unusable/malformed CSV, HTTP failure on the second asset, unknown-length chunked transfer, mid-stream cancellation, temporary/lock cleanup, retention of previous valid finals on download/validation failure, legacy nested imported models without manifests, and interrupted publish markers.

## Guarantees and limitations

- Each asset is written to a unique same-directory temporary file and flushed to disk. Both are validated before any final file is replaced. Final assets and the complete manifest are published with same-volume `File.Replace` for existing files or `File.Move` for new files; the pair is **not** a filesystem transaction. A flushed publishing marker makes an interrupted/failed multi-file commit unusable until a successful retry. There is no automatic publication rollback: an OS/filesystem failure after the first replacement can block a previously usable directory until the next successful download repairs the whole pair. Download/validation/cancellation failure before commit does not replace previous finals. The short commit phase is deliberately non-cancellable.
- A cross-process file lock prevents concurrent download publishers. A crash can leave temporary files, but they are never selected as ONNX assets. Normal failure/cancellation removes the current attempt's temporary files.
- Total downloaded asset bytes have a defensive 16 GiB disk budget, enforced both against declared lengths and streamed bytes (including chunked responses). This is a local resource policy, not a claimed official repository size; tests inject a small limit without large allocations. GET Content-Length must match when present. SHA-256 is checked against an injected expected hash and standard HTTP SHA-256 Digest/Content-Digest when provided. The default repository has no hard-coded guessed upstream checksums. The recorded local manifest is a completeness/change detector, **not** proof of upstream authenticity; HTTPS remains the transport trust boundary.
- Usability checks cache successful validation in a bounded in-memory cache (no sessions/weights retained). Cache identity includes full model/CSV paths, lengths, last-write and creation timestamps, and complete manifest contents including recorded hashes. A completed download seeds the cache after its background CPU validation. Repeated unchanged UI/artist-tag checks only read small manifest/stat information, not model bytes or another session. Changed freshness invalidates the cache: manifest-bearing models are rehashed/revalidated; imported models are revalidated. First checks after process restart/import or detected changes remain synchronous and may be expensive for a large model. Deliberate same-size tampering that also preserves file timestamps can evade the freshness cache until restart; this is not an adversarial filesystem security boundary. Legacy/imported models remain supported without creating/modifying their files or requiring a manifest.
- CPU session construction validates serialized graph/operators/weights and input/output presence; CSV uses the actual catalog parser and must contain usable rows. No numerical inference, image preprocessing correctness, real tagger quality/output alignment, GPU/DirectML execution, external-tensor asset download, large-model memory/performance, or real remote download has been verified by this test suite. CPU-unsupported custom/GPU-only graphs are not accepted by this check. No paid NovelAI requests or deployed service changes occur.
