# NAI Utility Mobile – 开发范围与验收（2026-10-11）

## 产品目标与分支
从 `Andy-linux/NAI-Utility-Tool` 的 Windows `dev`（当前基线 `cc28495`）移植为独立 Android / iPhone / iPad 客户端；手机无需 PC 在线，直连 NovelAI 官方或兼容的自定义 NyaProxy 根地址。桌面端 `dev/main`、网关及线上环境保持不变。仅在 `mobile-dev` 开发，开源发布沿用 GPL-3.0。

### 开发优先级（更新后的用户决定，高于 2026-10-10 旧规划）
**A｜生成核心，先完成并验收**
- 生成工作区：完整且按模型筛选的 NAI 模型（V3/V4/V4.5/V5）；Prompt/Negative/Style 编辑，Prompt 辅助以日常所需自动补全、权重高亮和基本操作为重点；
- 多角色（V5 上限 22，V4/4.5 上限 6），正负词、坐标位置、角色顺序与保留草稿；分辨率预设、手动尺寸、横竖交换及限制提示；
- 基础参数：Steps、Sampler、Scheduler、CFG、Seed 的随机/复制/恢复；高级参数：CFG Rescale、SMEA/Dyn、Variety+、质量/UC、支持性联动；V5 High/Medium 模式约束与 High 草稿回填；
- PNG / NAI 元数据读取、显示、导入生成/重绘参数，兼容历史由 NovelAI 产生的 PNG 和 Windows dev 的元数据格式，保留原 Seed、角色位置、参考图信息；
- 上述各项最终值必须进入**真实请求**，且与 Windows dev 的现行请求合同对齐：自定义 URL 不得回退官网。离线 Mock 必须逐字段比对；Android UI 实际操作、模拟器截图与一版 APK 是批次 A 交付门槛。

**B｜创作核心**
- 重绘工作区：Inpaint、图生图降噪、选图/结果回送、画笔/橡皮/矩形、遮罩反转/清理/撤销/重做/缩放/平移/预览、有效蒙版判断、分辨率与底图对齐、WEBP image/mask 导出；与 Windows dev inpaint/denoise 的 API 请求类型、像素语义一致；
- 不重造完整画布框架：先审查 ComfyUI Frontend 新 mask editor、SD.Next Kanvas(Konva)、InvokeAI Unified Canvas 和 MIT Konva/Fabric.js；许可核实后对 **Uno Skia 继续完善 vs 局部嵌入 WebView+Konva** 做真实触控/性能与复用比较，选一个实现，避免双轨重复开发。支持 Android 触摸、iPad 手写笔输入的结构，移动端不用依赖桌面 GUI；
- 图库工作区：图片历史、缩略图与详情、选择/收藏/删除/发送回生成或重绘、文件分享；不要把所有原始大图一次性解码；
- 生成任务管理：默认**60 秒可配置等待超时**（具体区分等待和执行预算并按现有 dev 规则处理）、用户设置的最大请求次数与重复请求保护，取消任务时停止后续发送；**暂不实现连续/无限生成**，不对状态未知的收费请求盲目重试。

**C｜官方核心 API 与日常辅助**
- Anlas/V5 额度：只读官方账户信息、订阅/额度、刷新、使用请求的账户身份一致性与官方付费基价/Opus资格显示；未知显示未知，不杜撰 V5 单次百分比；自定义 NyaProxy 仅用已经支持的白名单；
- NovelAI 文本辅助：沿用 dev 已验证的 /oa/v1/chat/completions 路径生成/修改 Prompt；
- **新功能**：本地提示词收藏/储存/编辑/搜索/分组/调用：正负词、风格词、角色词按用户操作需要保存、复用，使用平台私有数据持久化，不向 Git 提交用户数据；
- 官方 Upscale 与 Enhance：沿用 desktop dev 已核实的 API 及 UI 参数规则，能从生成结果/图库一键进入，输出可保存、导出和返回重绘；
- iPhone / iPad UI：手机单列标签/抽屉；平板宽屏双列/三域，显示区域、导航/安全区、键盘、分屏大小变化适配；不使用 Windows 版 148KB 主窗口直接缩放替代。

**暂不实现（明确排除）**
- 本地 ONNX 超分 / Tagger 反推、非官方复杂后期效果链/后期处理工作区、桌面自动化面板、完整 Wildcards 抽卡/权重工具集（仅保留 A 所需日常 Prompt 辅助）、Windows SuperDrop 与回收站整套实现；
- 连续/无限生成。
- 不应因此删掉 Windows 桌面现有功能；这些仅指移动端当前排期。

## 验收等级
每个子功能分别记录：
1. 源码/ UI 已存在；
2. 核心数据与协议测试通过；
3. Android 真实 APK 安装、启动、操作与截图通过；
4. 对官方/兼容代理的业务端点经**用户授权**实测通过（涉及付费生成，未经额外授权只做 Mock）。
第 1 级绝不声称第 3 或第 4 级完成。iOS 需 Mac Xcode 编译签名，Windows SDK 的 APK 不能替代 IPA。

## 已知必须修补
- `MobileGenerationClient` 和桌面 `NovelAIService` 的请求组装目前两份代码：定向契约比较，不能因“可编译”就视为功能一致；
- `MobileMaskCanvas.HasMask` 目前依据“存在非橡皮笔迹”，完全擦除也会误判；修为**有效 alpha 像素检测**；遮罩与原图 WebP 编码必须验证尺寸和语义；
- 流式中间帧不可当 final、ZIP 需实际解码校验；
- 重绘页面选中后切换生成模式，必须避免错误调用 `generate`，且需要独立 Inpaint / Denoise 模式；
- 当前阶段没有完成业务范围中的全部核心模块；必须更新旧 `MIGRATION_PLAN.md` 和 `STATUS.md`，避免“已实现”和“规划”混淆；
- `mobile-dev` 曾有大量未提交文件。只有提交到分支并真实构建、验证 APK 后才能发布可供使用的版本。

## 社区参考（查代码、协议和许可证，按实际体验取用）
- ComfyUI Frontend：<https://github.com/Comfy-Org/ComfyUI_frontend>，`src/composables/maskeditor/`、`src/stores/maskEditorStore`，从笔刷、缩放、图像/遮罩交互出发。
- SD.Next Kanvas：<https://github.com/vladmandic/sdnext-kanvas>，TypeScript + Konva，多触控画布、图层/遮罩/历史、导出工作流；必须检查具体子仓库 LICENSE/依赖。
- InvokeAI：<https://github.com/invoke-ai/InvokeAI>，统一画布产品体验/工作流程。
- Konva：<https://github.com/konvajs/konva>，MIT；React-Konva 并非 RN 组件，移动方案以 WebView 里的 Web Konva 为候选。
- Uno SKCanvasElement：<https://platform.uno/docs/articles/controls/SKCanvasElement.html>，目前宿主已采用，可继续复用 Sketch/transform 思路。
- 不照搬 ComfyUI 自身的节点图/推理后端，当前应用使用 NAI API，不运行本机扩散模型。

## 分发与交付约束
- 可先提供 `mobile-dev` 实验 APK，但必须在 GitHub 预发行/文件名中注明其实际完成范围，不能冒充 A/B/C 全部完成；
- 先达成 A 的一次真实 Android 构建及 UI 验收，再继续 B、C。整轮连续推进，遇普通阻碍优先等价绕行，避免无意义多层防御工具/门禁，做少量高价值的测试；
- 禁止带 Token、用户图片、生产配置、模型权重、logs/bin/obj 缓存提交；
- 仅推送 mobile-dev，清楚记录版本 SHA、APK 位置和 Android 安装状态及未完成功能。GPL-3.0 声明不得缺失。
